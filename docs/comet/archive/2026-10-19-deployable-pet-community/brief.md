# 目标

为「养宠成长记录与社区」附加题建立并上线一个公开可访问、域名稳定的部署骨架：证明作品已成功部署，同时把技术架构、构建链路和目录分层搭好，使后续 change 可以在同一域名下持续添加产品功能、调整视觉与交互，而不需要返工基础设施。

本 change 只对「链接可用 + 部署可迭代」负责。产品定位、功能模块与视觉设计留给后续 change。

# 范围

- 保留已初始化的 Vite + React + TypeScript 技术栈，补齐 react-router-dom。
- 建立最小应用壳：品牌栏（爪记 PawLog）、部署状态卡、构建信息（版本/提交/构建时间）、后续迭代说明。
- 建立路由骨架：`/`、`/health`、`/community`、`/friends`、`/me` 五个入口，每个入口渲染带标题的占位页，用于验证 HashRouter 与后续页面扩展方式。
- 建立可迭代目录分层：`src/pages`、`src/components`、`src/lib`、`src/styles`，并在 README 说明新增页面/模块的步骤。
- 建立构建与部署链路：Vite 使用相对 `base`；GitHub Actions 在 push 到 `main` 时构建并发布到 GitHub Pages；`public/.nojekyll` 防止 Jekyll 处理。
- 固定公开仓库名 `pawlog`，固定访问地址 `https://fffsir.github.io/pawlog/`。
- 部署信息通过构建期环境变量注入页面，便于确认线上版本与最新提交一致。
- README 记录产品背景、技术栈、目录结构、本地开发、构建、部署、固定域名和后续迭代流程。
- 基础响应式：390px 手机宽度无横向滚动，桌面端内容居中并限制最大宽度。

- 登录、后端、数据库、实时聊天、地图、图片上传、支付。
- 自定义域名、备案、CDN 或国内服务器。

上述内容留给后续 change，在当前骨架之上迭代。

# 验收示例

- A1：在未登录的浏览器中打开固定地址，页面正常渲染，显示「爪记 PawLog」名称和明确的「部署成功 / 雏形已上线」状态，不出现白屏或报错。
- A2：页面展示构建信息（版本号、提交短 SHA、构建时间），且与当前 main 分支最新提交一致，可用于确认线上版本。
- A3：五个路由入口均可通过底部导航或页面链接访问；直接打开带 hash 的地址（如 `/#/health`）以及在该地址刷新时，都能正确渲染对应占位页。
- A4：构建产物中的 JS/CSS/图标引用为相对路径，在 `/pawlog/` 子路径下加载成功，不出现 404。
- A5：`npm run build` 与 `npm run lint` 均成功退出；构建结果包含可直接静态托管的 `dist/`。
- A6：仓库包含 `.github/workflows/deploy.yml`，push 到 `main` 后 GitHub Actions 成功完成构建与 Pages 部署；固定地址返回 200。
- A7：README 记录固定域名、技术栈、目录结构、本地开发、构建、部署方式，以及「新增一个页面/模块」的迭代步骤。
- A8：在 390px 视口下页面无横向滚动、导航不溢出；桌面端内容居中且最大宽度受限。

# 约束与不变量

- 纯静态站点：不得依赖自建后端、数据库或需要密钥的第三方服务。
- 路由必须使用 HashRouter，Vite `base` 使用相对路径，确保 GitHub Pages 子路径部署和刷新均可用。
- 不得依赖外部图片、字体或 CDN，保证国内访问稳定。
- 面向用户的文案使用中文。
- 仓库必须为公开仓库，域名固定为 `https://fffsir.github.io/pawlog/`；后续迭代不得更换仓库名或域名。
- 构建必须通过 `npm run build` 和 `npm run lint`。
- 页面与路由必须按 `src/pages`、`src/components`、`src/lib`、`src/styles` 分层；新增路由只改路由表和新增页面文件，不修改部署链路。
- 构建信息只使用构建期注入的公开值，不包含密钥或个人信息。

# 决策

- 使用 HashRouter，避免静态托管子路径刷新 404。
- 使用 GitHub Pages + GitHub Actions 作为唯一部署方案，固定仓库 `pawlog`。
- 构建信息通过 `VITE_BUILD_VERSION`、`VITE_COMMIT_SHA`、`VITE_BUILD_TIME` 在 Actions 中注入，本地构建使用默认值。
- 页面采用极简但成型的视觉基线：暖米色背景、绿色主色、圆角卡片；不在此 change 展开品牌视觉设计。
- 五个路由占位页用于验证路由与导航结构，后续 change 直接替换对应页面内容。
- 不在本 change 引入状态管理库、图表库或 UI 组件库，避免为未确定的产品功能预设约束。
- README 作为迭代入口，明确后续 change 的功能、视觉和内容分别从哪里开始。
